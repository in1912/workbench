# 个人工作台（Personal Workbench）

自托管的个人效率中枢：信息聚合、任务管理、家庭与子女跟进、学习成长、效率工具、AI 能力，一条命令 Docker 部署。

## 功能一览

| 模块 | 说明 |
|------|------|
| 用户与权限 | 多用户登录（密码 scrypt 加盐哈希存储）、管理员/成员角色、按页面授权（哪些页面可打开） |
| 今日看板 | 天气、今日待办/日程、快捷启动、科技新闻、子女任务一屏总览 |
| 每日新闻 | 科技 / 生活 / 本地三类，每天 08:00 自动抓取各 5 条，含摘要与出处；本地新闻按天气城市自动过滤；历史新闻留存 90 天可按日期翻阅 |
| 邮箱 | IMAP 连接任意邮箱，拉取最新邮件**含正文**、标记已读 |
| 笔记 | Markdown 笔记，分类管理，支持 AI 总结 |
| 待办与日程 | 待办事项（优先级/截止日期）、日程登记 |
| 家庭与子女 | 家庭事项登记、孩子档案、学习任务下发与完成跟进 |
| 学习成长 | 学习计划、学习记录（收获/问题）、AI 一键生成复盘草稿并保存 |
| 效率工具 | 剪贴板历史（含 Windows 自动采集脚本）、快捷启动常用应用 |
| 业务系统与 AI | 登记公司业务系统（网页直连 / API 代理 / 用户名密码加密存储），**Skill 引导词任务**：每个系统可建多个 Skill（引导词+指令+数据接口+cron 定时），AI 助手中输入引导词即执行，定时结果自动写入每日待办 |
| 全局搜索 | 跨笔记、待办、家庭、子女任务、学习记录、剪贴板、新闻的全文搜索 |
| 定时任务 | 每天 08:00 自动抓取新闻；Skill 按各自 cron 执行；每周日自动清理 90 天前的旧数据 |
| 升级管理 | 版本代码打包 + 增量升级（仅管理员）：与基线比对自动检测改动文件，打包为升级包（源码 + 前端构建快照 + manifest）存入 `data/upgrades/`；服务器端可上传升级包一键应用（覆盖文件后自动重启）；升级日志全程记录版本号与升级内容 |

## 首次使用

1. 打开 `http://<地址>:3000`，使用管理员账号 **admin** 登录（密码为你自己设置的密码；全新部署时默认 admin / 123456）
2. **立即修改密码**：设置 → 账号与安全
3. 设置 → 天气（城市）、AI 配置（模型/接口/Key，配置页下方可直接**查询余额**）、邮箱（IMAP）
4. 用户管理（独立页面，仅管理员可见）：添加成员并勾选其可访问的页面

## Docker 部署与开机自启（推荐）

```bash
# 本机打包（含源码 + data 数据目录，不含 node_modules）
bash pack-deploy.sh          # 生成 workbench-deploy.tar.gz

# 上传到服务器 / 群晖后：
tar xzf workbench-deploy.tar.gz
cd workbench-deploy
docker compose up -d --build
```

- **开机自启**：`docker-compose.yml` 已配置 `restart: always`——Docker 服务一启动（Windows 开机自动拉起 Docker Desktop / 群晖开机自动启动 Docker 套件）容器即自动运行，无需手动
- **数据持久化**：数据库在宿主 `./data` 目录（卷挂载），升级/重建容器数据不丢
- **首次启动自动迁移**：容器会用 `data/` 目录里最新的历史库自动导入全部数据（账号、待办、新闻、通勤配置等），部署即无缝衔接
- **本机也可先做 Docker 迁移验证**：本机装了 Docker Desktop 后执行 `docker compose up -d --build`（需先停掉本地 node 服务，避免 3000 端口冲突）

## 版本升级流程（本地改代码 → NAS 生效）

首次部署用上面的全量打包；之后的日常改动走**增量升级包**，全程网页操作、不用 SSH：

1. **本地构建前端**：`cd web && npm run build`（只改了后端可跳过）
2. **本地工作台 → 升级管理**：点「检测改动」→ 自动勾出新增/修改的文件 → 填版本号和升级内容 → 「打包并记录」。
   升级包（zip）= 选中源码 + 最新前端构建快照 + `manifest.json`/`UPGRADE.md`，自动存入本地 `data/upgrades/`
3. **下载升级包**，传到 NAS（网页上传、File Station 拖拽均可）
4. **NAS 的工作台 → 升级管理 → 应用升级包**：选择 zip → 「上传并应用」。
   服务会校验包、覆盖 `server/` 源码与 `web/dist/` 快照、写入升级日志并标记当前版本，然后自动重启（`restart: always` 自动拉起），几秒后刷新页面即新版本
5. 两端「升级管理」页顶部都能看到**当前运行版本**，升级日志区分「打包」与「已应用」

注意：
- 升级包应用在**容器内**生效；下次 `docker compose up -d --build` 重建容器时会回到镜像内的代码——所以阶段性（或涉及 data 目录变化时）仍做一次全量打包部署，把最新代码固化进镜像
- 本地直跑（非 Docker）应用升级包后进程不会自动重启，需手动重启服务

## 数据存储说明（重要）

- **本机直跑**（`node server/index.js` 或 start.bat）：主库为 `data/workbench.sqlite`（稳定单库，不随重启累积）
- **Docker 运行**：固定使用 `data/qg-final.sqlite`（容器内 `/data` 卷），同一文件持续沿用
- **首次启动自动迁移**：从旧版 `qg-<时间戳>.sqlite` 历史库一次性导入全部数据，并把历史库归档到 `data/archive/`（移动而非删除，可恢复）
- **备份**：备份 `data/` 目录下**主库 + 全部 `tenant-*.sqlite` 租户库**才是一份完整数据（主库存账号/系统级配置/共享模块数据，每个成员的业务数据在自己的租户库里）
- ⚠️ 切勿把 `data/` 放在云同步盘（夸克网盘 / Synology Drive / OneDrive / 坚果云）目录下——同步程序会锁定 SQLite 文件导致写入失败。默认位置已规避；如需自定义，设环境变量 `DATA_DIR` 指向非同步目录

## 多成员（多租户）说明

系统支持类 SaaS 多成员：管理员在「用户管理」新建账号后，每个成员是一个独立"租户"：

- **完全隔离**（每人自己的）：笔记/待办/日程/邮箱配置与邮件/文件存档/AI 对话记录/账单/学习/家庭档案/业务系统与 Skill/看板布局/天气城市/通勤地址/每日默认待办模板等
- **可共享模块**（管理员在「设置 → 模块共享设置」开关控制，默认全开）：新闻抓取、节日信息、高德地图 Key、AI 配置
  - 共享开启时由管理员统一配置（其他成员设置页该模块显示 🔒 禁用），全员看到同一份数据
  - 关闭后各成员独立配置自己的（历史共享数据不迁移，独立后从空开始）
  - 本地新闻始终按**各成员自己的天气城市**过滤展示
- **系统名称**仅管理员可改（全员同步）
- 删除成员时其租户库自动归档到 `data/archive/user-<id>-<时间戳>/`（可恢复），不物理删除

## 业务 Skill 使用说明

1. **业务系统** 页：添加系统，填名称、地址，API 类型可填 Token（Bearer）或 用户名/密码（Basic，密码加密存储）
2. **Skill 任务** 页：为每个系统添加多个 Skill——「引导词」（如"今日订单汇总"）+ 任务指令 + 可选数据接口路径 + 可选 cron 定时
3. 在 **AI 助手** 中输入引导词即可执行对应任务（自动带系统凭据调用数据接口，AI 分析后返回结果）
4. 配置了 cron 的 Skill 会定时执行，**结果自动写入当日待办**，在「今日看板」中查看

## 快速启动（Docker）

```bash
docker compose up -d --build
```

访问 `http://localhost:3000`。数据保存在 `./data/`（主库 workbench.sqlite + 各成员 tenant-*.sqlite），备份整个 data 目录即可完成数据备份。

## 局域网访问

服务默认监听 `0.0.0.0:3000`，同局域网内的手机 / 平板 / 其他电脑直接访问 `http://<本机IP>:3000` 即可。

- 本机 IP 查看：`ipconfig`（找"IPv4 地址"，如 `10.10.125.94`）
- Windows 防火墙：首次需放行 3000 端口入站（管理员 PowerShell 执行）：
  ```powershell
  netsh advfirewall firewall add rule name="Personal Workbench 3000" dir=in action=allow protocol=TCP localport=3000
  ```

## 数据存储位置

| 部署方式 | 数据文件 | 说明 |
|---------|---------|------|
| Docker | `./data/qg-final.sqlite` + `./data/tenant-*.sqlite`（容器内 `/data`） | 主库 + 各成员租户库，同在 data 文件夹 |
| Windows 本地 | `./data/workbench.sqlite` + `./data/tenant-*.sqlite` | 默认项目目录下的 data 文件夹；可用 `DATA_DIR` 环境变量覆盖 |

> **注意**：请勿把 `data/` 放在云同步盘（夸克网盘 / Synology Drive / OneDrive / 坚果云等）目录下——同步程序会反复锁定 SQLite 文件，导致"保存失败 / 写入挂起"。默认位置已规避；如需自定义，设环境变量 `DATA_DIR` 指向非同步目录后启动。

## 首次配置

1. **天气**：设置 → 输入城市名 → 「保存并定位城市」（免费接口，无需 key）
2. **邮箱**：设置 → 填写 IMAP 服务器 / 账号 / 密码（建议用邮箱服务商提供的"授权码"，如 QQ 邮箱、163 邮箱均支持 IMAP）
3. **AI**（可选但强烈建议）：设置 → 填模型名称 / API 地址 / API Key，任意 OpenAI 兼容服务均可（DeepSeek、通义千问、Kimi、OpenAI 等）
   - 配置 AI 后：新闻摘要、笔记总结、学习复盘、AI 助手全部启用
4. **新闻源**：默认内置科技/生活/本地 RSS 源（均为实测可用源）。**本地新闻**目前无通用的按城市 RSS（百度/Bing 均已停止 RSS 服务），默认用全国综合兜底，建议在设置中把「本地」替换为你所在城市/本地的 RSS 源；**历史新闻**按天留存 90 天，新闻页顶部日期下拉可翻阅往日新闻

## Windows 剪贴板自动采集（可选）

工作台跑在局域网机器时，Windows 电脑运行：

```powershell
powershell -ExecutionPolicy Bypass -File scripts/clipboard-watcher.ps1
```

脚本开头把 `$BASE` 改成工作台地址（如 `http://192.168.1.10:3000`），每 3 秒自动把系统剪贴板新内容推送到工作台。

## 技术架构

```
Vue 3 + Vite（前端单页应用）
        │ REST API
Express + node:sqlite（Node 内置 SQLite 驱动；中文全文检索用 LIKE + 索引）
        │
node-cron 定时任务 · rss-parser 新闻抓取 · imapflow IMAP 邮箱
Open-Meteo 天气（免费） · OpenAI 兼容 AI 接口（可配置）
```

## 常见问题

- **新闻抓不到**：容器需要能访问外网；个别 RSS 源失效可在设置中替换；本地新闻依赖天气城市已配置。
- **邮件连不上**：确认邮箱服务商已开启 IMAP，端口 993/TLS；部分邮箱（QQ）需在邮箱设置里开启"IMAP/SMTP 服务"获取授权码。
- **AI 报错**：确认 base_url 以 `/v1` 结尾（如 `https://api.deepseek.com/v1`），模型名称与该服务一致。
